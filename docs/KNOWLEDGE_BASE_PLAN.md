# 知識ベース設計 — 何を組み込むべきか

PHsupport の価値は LLM ではなく `data/` にある。ここに「進出担当者が最初に見るべき資料」と「専門家が実際に使っている論点の切り方」を集めておけば、答えは創作されず、案内は外れない。

## 1. 設計思想

- **答えを持たない。案内だけ持つ。** 数値（最低賃金・税率・最低資本）は変わる。DB に入れるのは「その数値はどこに載っているか」「どの機関が決めるか」「いつ改定されるか」。
- **論点 × 資料の二層。** `topics.json`（論点：相談者の困りごとを専門家の言葉に翻訳する）と `sources.json`（資料：読む順番と、その資料で何が分かるか）。両者を id で結ぶ。
- **口語キーワードを厚く。** 相談者は「人を雇いたい」「店を出したい」と書く。「労務」「外資規制」とは書かない。
- **要確認フラグを恥じない。** `verify_flag` / `url_verified` を正直に付け、次に触った人が更新できるようにする。

## 3. 次に入れるべきもの（優先順）

### 優先 A — 数値の一次資料をピン留めする
今は「NWPC を見ろ」で止まっている。次は資料側に **「この URL のこの表」** まで落とし込む。
- NWPC 最新 Wage Order（NCR / Region IV-A / Region VII）— 日額最低賃金
- BIR Revenue Regulations（CREATE MORE 施行規則 RR）— ITH/SCIT/ED の適用細則、VAT ゼロ税率の範囲
- FIRB / BOI の SIPP 最新版（Tier I/II/III の業種表）
- PEZA 認定 IT ビル・特区の一覧（Excel/PDF）
- SEC eSPARC の必要書類チェックリスト
- DOLE AEP 申請書類・料金表
- JETRO 投資コスト比較の当年版（マニラ・セブの数字）

### 優先 B — 「他社の失敗」を論点に埋める
JETRO 実態調査・JCCIPI 部会・弁護士事務所のニュースレターから、**日系企業が実際に踏んだ地雷**を `key_points` に入れる。
- 税務調査（LOA）で VAT インプット否認された事例
- 試用期間の評価基準未明示で正規化された事例
- 現地パートナーの名義貸しで Anti-Dummy 法に触れた事例
- 資本金の BSP 未登録で配当送金に詰まった事例
- Tax Clearance に 2 年かかった撤退事例

### 優先 C — 業種別の深掘り論点を追加
現在の 16 論点は横断的。業種ごとに 1 論点ずつ足す。
- 飲食・小売：RTLA（₱2,500万）、フランチャイズ、FDA LTO、ハラル、Sari-sari 流通
- 製造：PEZA 通関（Import Permit）、原産地規則、ロジスティクス（マニラ港 vs バタンガス港）
- IT-BPO：CREATE MORE の WFH 比率、NPC 登録、給与相場（IBPAP）
- 医療・介護：フィリピン人看護師・介護士の EPA 受入れとの接続、PRC 免許
- 再エネ・インフラ：DOE 通達、PPP 法（2023 改正）、地方自治体の許認可
- 教育・人材送出：POEA/DMW 規制、日本語教育、特定技能との接続

### 優先 D — 相談窓口を「人」の粒度で
`sources.json` に `type: "相談窓口"` を増やす。JETRO マニラ、JICA フィリピン事務所、中小機構の専門家相談、JCCIPI 各部会、在マニラの日系会計事務所・法律事務所（固有名は載せず、選び方の基準を載せる）。

### 優先 E — 英語版・フィリピン側の視点
フィリピン側パートナーに見せる想定で、`title_en` / `summary_en` を論点に追加。DTI の「Doing Business in the Philippines」、PEZA の Investor Guide を英語資料として整理。

## 4. 運用ルール

1. 数値を書くときは **必ず「（年月時点）」** を付ける。
2. `verify_flag: true` の論点は、四半期に一度、一次資料と突き合わせる。
3. `url_verified: false` の資料は、発行元トップから辿って正しい URL に更新するか、`url` を発行元トップに戻す。
4. 論点を足したら `npm run kb:check`。
5. 「専門家に聞くこと」は**そのまま口に出せる文**にする。抽象的な問い（「税務について教えてください」）は入れない。

## 5. 将来：RAG への拡張

今はキーワード照合（依存ゼロ、Vercel Function で即動く）。資料が 100 件を超えたら、
- `sources.json` の `why` + `title` を埋め込み（Voyage / OpenAI embeddings）して Supabase pgvector に載せ、
- `retrieve()` を「キーワード + ベクトルのハイブリッド」に差し替える。
`api/_kb.js` の `retrieve()` のインターフェース（`{ topics, sources }` を返す）を変えなければ、他は触らずに済む。
